# Native D3D11 bridge contract

`DSPAANative.dll` exposes the version-2 Windows x64 C ABI in `native/bridge/api.h`. The 112-byte frame preserves the entire original 96-byte prefix, then appends `outputWidth`, `outputHeight`, `quality` and `reserved2` at offsets 96/100/104/108. `width`/`height` describe the input resources. Status remains 288 bytes; optimal settings are 300 bytes. Both frame reserved fields must be zero; consumers must check the ABI before submission. It reuses the same `NgxDevice`/`DlssFeature` backend as the headless probe, rather than implementing a separate approximation of DLSS.

## Thread and resource ownership

- `DspAaInitialize` validates paths and initializes diagnostic output; no NGX device is created on the calling/main thread.
- A frame contains stable `ID3D11Resource*` inputs: input-sized RGBA16F color, R32F depth and RG16F motion vectors, plus output-sized RGBA16F output. DLAA requires equal dimensions; SR allows smaller input dimensions. Every texture is single-sample, single-mip, single-slice and belongs to the same D3D11 device. Output requires UAV support; inputs require SRV support. Resource formats may be those float types or their exact corresponding typeless backing formats (`R16G16B16A16_TYPELESS`, `R32_TYPELESS`, `R16G16_TYPELESS`); arbitrary integer/normalized siblings are not accepted. The caller owns the originals; each queued frame additionally retains COM references.
- `DspAaQueueFrame` copies scalar parameters and returns an opaque, non-dereferenceable token. Submit it once with the returned render callback, event ID `1`, through Unity's `IssuePluginEventAndData`. Initialization, feature creation/recreation, evaluation and release then occur on the render-thread consumer. NGX is not thread-safe; callers must issue render events in order on one consumer. The internal mutex does not promise reordering of concurrently invoked callbacks.
- Frames, capability queries and optimal-settings queries share bounded backpressure. A null submission must use the caller's fallback, never be treated as a completed DLSS frame or a ready query. Release/shutdown commands remain available when the frame budget is full.
- Cancel only a token that has **not** been submitted to the renderer. Cancelled, unknown and duplicate tokens are harmless. Pointer-size tokens are identifiers, not heap addresses handed to Unity.
- Queue a camera release after all its frames and queries. A returned status `2` acknowledges retirement and is consumed by the first status read; only then should managed owners free their stable textures. Queue shutdown after releases. Shutdown destroys features before the NGX device and rejects new submissions while closing.
- Keep the DLL loaded while Unity can hold callback addresses. No finalizer or DLL loader-lock destructor calls the graphics driver. If rendering stops before queued shutdown executes during process exit, the OS reclaims the remaining process resources. Hot unload is unsupported.

## Capability queries

The additive `DspAaQueueSupport(deviceResource)` / `DspAaGetSupport(token, output)` exports preserve the existing version-2 frame and status layouts. The support payload is 264 bytes: `uint32_t size`, `int32_t result`, and a 256-byte UTF-8 message. Set `size` before reading. `GetSupport` returns whether the token has a record; `result` is **0 pending, 1 available, -1 unavailable/error**. A terminal result is consumed exactly once; pending reads do not consume it.

Submit the token through the same render callback. Its retained resource identifies the actual rendering device, not a separate adapter chosen by name. The consumer checks the adapter and uses the rendering backend's NGX initialization and `SuperSampling_Available` query. The backend also reports a required driver update and minimum version when NGX provides those fields. No DLSS feature, preset selection or driver-profile change is performed by this check. A successful capability result does not prove support/performance of every explicit model or complete frame integration.

Unsubmitted cancellation removes the request and releases its anchor. The producer must retain its Unity anchor until a terminal result; shutdown clears all remaining records. Pending queries and unread terminal results are bounded. The managed integration queries lazily when graphics settings are opened or a saved DLSS configuration needs rendering; other AA modes do not require loading NGX first. Pending/unavailable DLSS cannot be newly selected, and its reason appears in the graphics menu without overwriting saved settings.


## Resolution queries

The wire quality values are **0 DLAA, 1 Quality, 2 Balanced, 3 Performance, 4 Ultra Performance**. They are not the NVIDIA enum values; the bridge explicitly maps them. Resolution mode and model preset are independent. Changing either, or either pair of dimensions, recreates the temporal feature.

Call `DspAaQueueOptimalSettings(camera, deviceResource, outputWidth, outputHeight, quality)` with an owned D3D11 resource from the actual rendering device and submit the returned token through the same render event (`1`). The producer only retains that anchor; it performs no NGX initialization or D3D context work. The consumer queries `NGX_DLSS_GET_OPTIMAL_SETTINGS` with capability parameters, not freshly allocated feature parameters. DLAA returns the exact output dimensions directly; SR has no hardcoded sizing fallback.

`DspAaGetOptimalSettings` returns whether a record exists, not whether it succeeded. Set the output struct's `size` before calling. Inspect `result`: **0 pending, 1 ready, -1 error**; the returned output dimensions and quality identify the request. An accepted replacement immediately resets the record to pending. Older completion/cancellation cannot replace or erase a newer request. Cancellation of the current unsubmitted token removes its pending record. Camera release and shutdown remove query records and retire retained anchors. Use the returned `optimalWidth`/`optimalHeight` for fixed-resolution rendering; min/max are the SDK's supported dynamic range, not a request to enable dynamic resolution.


## Model verification and fallback

Preset hints are applied at feature creation. Dimensions, preset and creation flags participate in configuration equality; changed configuration releases/recreates the feature and resets temporal history. An explicit frame reset also invalidates history without requiring a new configuration.

Each camera/configuration captures its own creation-log evidence. A previous camera's selection is not accepted as new evidence. Driver override diagnostics, missing evidence or a mismatched selection fail the frame. Log parsing is deliberately conservative and is not a stable NVIDIA query ABI.

The Unity adapter obtains camera depth and motion using `BuiltinRenderTextureType.Depth` and `BuiltinRenderTextureType.MotionVectors`. A string `RenderTargetIdentifier` names a `CommandBuffer.GetTemporaryRT` allocation, not an arbitrary globally bound Shader texture.

Camera projection jitter and NGX jitter are different coordinate quantities. The managed adapter shifts Unity's frustum by the centered Halton sample and submits the **opposite** sample through `Jitter.ToNgx`, matching the resulting D3D11 render-texture pixel displacement. The original projection and the TAA/DoF jitter vector keep their Unity convention. NGX guide §3.7.3 requires render-pixel offsets in the same coordinates as its motion vectors; Unity's [2022.3 DLSS integration](https://github.com/Unity-Technologies/Graphics/blob/2022.3/staging/Packages/com.unity.render-pipelines.high-definition/Runtime/RenderPipeline/RenderPass/DLSSPass.cs) likewise negates `taaJitter` at the API boundary. Do not negate the native backend again: it accepts already-converted offsets.

Rejected frames report the failing texture role and expected/actual descriptor in status. `ngx.log` additionally records all four input/output resource descriptors (dimensions, numeric DXGI format, sampling, mip/array counts and bind flags), so another rejection does not hide subsequent mismatches. Validation remains strict; diagnostics do not make an incompatible texture valid.

The caller spatially upscales the actual input into the output before the native event (a direct copy is sufficient for DLAA). For validated equal-size color/output resources, an evaluation failure restores the source copy. For unequal sizes, the bridge maintains a reusable per-camera full-output-size backup and captures the prefilled output immediately before evaluation; even a partial NGX write followed by failure is restored exactly from that backup. It never copies low-resolution color directly into unequal-size output. Pre-validation and feature-creation errors leave the SR prefill untouched and do not allocate/copy a backup. Failure records an error and drops the feature and backup; release, shutdown and device replacement also retire them. The output can still be a jittered raw frame; this is an image/lifetime safeguard, not a claim that a failing frame received temporal AA. The main-thread adapter can revert to the game's AA on receipt of the error.

The official NGX D3D11 API saves/restores immediate-context state (integration guide section 5.2.5). The switching probe additionally checks selected viewport/topology/compute-shader state across calls; it is not an exhaustive proof of every binding or a substitute for Unity testing.

## FSR extension and cross-API ownership

FSR is an additive extension of ABI 2; it does not reinterpret the frame's reserved fields. `DspAaQueueFsrFrame(frame, parameters)` takes the same 112-byte frame plus a **40-byte** `DspAaFsrParameters`: size, near/far clip distances, vertical FOV in radians, pre-exposure, view-space-to-meters, sharpening strength, zero reserved word, then an optional opaque-only color pointer at offset 32. The optional texture is input-sized RGBA16F/SRV on the same D3D11 device and is retained with all other frame inputs. The caller supplies perspective camera parameters, physical near/far distances, finite positive exposure/scale and sharpening in [0,1]; the backend handles reversed-depth near/far ordering. Preset/model evidence applies to NGX only.

`DspAaQueueSupportForBackend(resource, backend)` and `DspAaQueueOptimalSettingsForBackend(camera, resource, width, height, quality, backend)` use backend **0 DLSS / 1 FSR**. Existing exports retain DLSS semantics. FSR quality 0 means Native AA; the four SR values retain the same order. `DspAaGetFsrOptimalSettings` uses a **304-byte** structure: the existing 300-byte settings prefix followed by SDK-provided `jitterPhases`. Set its nested `settings.size` to 304. Pending/stale/cancellation and bounded-token rules are shared, and a result must belong to the requested backend. Native AA also queries the FSR SDK for its jitter cycle.

The game remains D3D11. The bridge queries that device's adapter, creates a D3D12 device/queue on the **same** adapter, and exchanges textures using NT shared handles and shared fences. D3D12-created shared images have `ALLOW_RENDER_TARGET | ALLOW_SIMULTANEOUS_ACCESS`; UAV destinations additionally allow unordered access. Unity resource pointers do not become D3D12 resource pointers by casting. Copies, producer/consumer GPU waits, and allocator-reuse CPU retirement have real cost; this is not a zero-copy or zero-overhead path.

The official AMD loader enumerates providers for the actual device. Creation explicitly overrides to the analytical 3.1 provider (at least patch 5) and verifies the created provider identity. ML 4.x is never selected as a fallback; the upscaler DLL/API's 4.1.1 version is distinct from the chosen algorithm. FSR capability checks shared resource formats, SM 6.2 and interop without an NVIDIA-only gate.

For FSR, the Unity adapter captures opaque color at `BeforeForwardAlpha`, before transparent geometry. The SDK generates an R8 reactive mask from opaque/current color using its sample's tonemap/threshold/max-component configuration. This is a transparency heuristic, not true object motion and not an FG UI-alpha input. The main frame still contains transparent geometry. Current exposure is passed as 1 with SDK auto-exposure; no global texture mip-bias override is applied.

Each evaluation copies D3D11 inputs, signals the producer fence, dispatches on D3D12, signals completion and queues D3D11 output consumption. Three allocator/list slots wait for their own completion before reuse. Dimension/flags/reactivity changes drain before recreation. FSR failure before output consumption leaves the caller's SR prefill untouched (or copies equal-sized source); no partial SDK output is copied back. Camera retirement, shutdown and device replacement explicitly drain GPU use before destroying contexts/resources/modules. If fault recovery cannot establish retirement, the feature quarantines its shared owners until process exit instead of freeing in-flight GPU storage. Nothing performs graphics teardown from DllMain.

## Experimental presentation interface

The opt-in FG integration uses the separate version-3 ABI in `native/present/api.h`; it does not change the SR frame ABI above. The presentation input envelope is 456 bytes: `logicalOutputWidth` and `logicalOutputHeight` are appended at offsets 448 and 452. Configuration, begin and status structures remain 32, 24 and 472 bytes; consumers must check the presentation ABI independently of the SR ABI. The early bootstrap installs hooks before the game creates its graphics device and swapchain. It supplies the D3D11-facing/D3D12 presentation owner at the intercepted swapchain creation; loading the ordinary SR plugin later never creates a second presentation owner.

The packaged entry is `patchers/DSPAASR.Preloader.dll`, discovered by BepInEx 5 through its empty `TargetDLLs`, `Patch` and `Initialize` members. It reads only the active profile's saved FG backend. Off records an inactive result without loading the native early entry; an enabled request locates the profile's unique active payload, validates managed identity and native ABIs, pins the native DLL and invokes bootstrap ABI 1 outside the loader lock. No game-root files or `boot.config` are modified. Partial failure is not retried or unloaded in-process. The older XR pre-init wrapper is a developer probe route, not a required package installation step.

A versioned AppDomain receipt carries startup intent and `Inactive/Started/Failed` plus the selected payload directory; its absence is a distinct installation failure, not equivalent to Off. `Started` certifies only that hooks were installed. The ordinary plugin still uses the actual presentation channel's availability and SDK capabilities; it does not load the patcher to obtain a receipt. A normal inactive session can save a next-start request without claiming hardware support. Once a bridge is available, Off/FSR/DLSS transitions use the existing channel without restart; turning generation off does not tear down the bridge. Returning to the original presentation path occurs on the next process start with Off saved.

The before-input call allocates the application frame ID and runs the applicable Reflex pacing. Render event `1` marks render submission. At the main world camera's `CameraEvent.AfterEverything`, event `3` snapshots its currently bound D3D11 color attachment, after world postprocessing and before screen UI. The logical swapchain surface supplies device/format/generation constraints, not current world pixels: Unity can update it only in a later final blit. The snapshot retains the attachment's dimensions and sRGB-view evidence and preserves its storage bytes. Event `2` consumes the end-of-frame envelope and binds only a snapshot matching its frame ID, generation and declared logical output dimensions. Missing/stale inputs pause generation without suppressing the real Final. Explicit native producers may instead supply their own correctly encoded HUDless resource.

Three domains remain distinct: the temporal raster R (`renderWidth`/`renderHeight`), logical world output L (`logicalOutputWidth`/`logicalOutputHeight`), and physical swapchain D. Both logical dimensions being zero declares an already canonical, display-sized H. Otherwise H must match L. An explicit, positive, in-bounds `generationRect` maps content into D. For Unity's scaled-output path with a zero rectangle and L different from D, the transport reads the actual D3D11 viewport at the Final-copy boundary; it requires one finite, integer, nonempty, in-bounds viewport. It does not infer an aspect-fit rectangle: Unity's final-blit quantization can differ from either flooring or rounding L/D arithmetic. An invalid layout leaves the original Final presentable and rejects generation for that input.

Only a logical image requiring a size/region change receives the shared D3D12 resampling pass. The captured sRGB view selects decode/filter/encode behavior; it is not a guess based on FP16 storage or a second postprocessing pass. H becomes display-sized with the content in the same region as Final; Final itself is unchanged. The same-domain path retains its ordinary copy. Explicit standalone presenters continue to accept their existing same-encoding, different-storage-format inputs and retain their conversion fallback. Logical/raster/region changes reset temporal history even if the swapchain dimensions do not change.

Ordinary world-space geometry, including ordinary world-space UI, stays in the world image. The navigation board is a narrow exception: its original text/Canvas is drawn after H and before the following screen camera, with an EOF fallback when no later display camera occurs. Its existing SR-only path stays after reconstruction and before the game's remaining postprocessing. The Canvas adapter preserves the original material, text and transforms. It borrows an unused unnamed layer during `Canvas.preWillRenderCanvases`, before Unity prepares the Canvas batches; camera pre-cull continues that same frame's scope and refreshes the view, projection and viewport instead of restoring and borrowing the layer again. A missed early preparation is rejected rather than attempted too late. The layer is restored after explicit rendering or scope cancellation. An early-isolated SR board is returned to the original postprocessing input when that frame cannot enter reconstruction. Unity has no exclusive runtime layer reservation. Early capability rejection leaves the board in its original world pass, keeps SR usable, and makes that FG frame original-only. Late rendering or restoration failures remain errors: restoring state cannot guarantee replacement of navigation pixels already omitted from that frame.

When FG relocates the navigation board, its light source is also rendered into an isolated, logical-output-sized linear HDR texture using the original text materials. A separate instance of the game's Bloom component consumes that source, the actual main-camera Bloom settings and the same frame's already-computed exposure. It does not advance exposure history or replay the world's postprocessing. The original text is still drawn directly into Final with its original blending; the isolated texture's alpha is never used as coverage. An `AfterEverything` command buffer on the explicit navigation camera copies its current CameraTarget and adds only the prepared bloom through the game's Uber shader, with unit exposure for the already-processed background. This final draw uses the game's screen quad with explicit geometry, base-texture binding and Bloom UV orientation: on top-origin graphics APIs, the screen copy and camera-rendered HDR source have different vertical conventions. The camera's view/projection and viewport are restored after the draw. Both navigation draws share the same early Canvas isolation scope. H is captured before either the navigation text or its glow is added; generated frames continue to use the existing Final/H SDK path without a new UI-alpha surface.

This is a navigation-specific bloom approximation: the isolated light source does not reproduce world occlusion, nonlinear threshold interactions with the background, or the entire world grading/distortion stack. It must not be generalized to ordinary world-space UI. Shader/target capability checks precede navigation suppression. If HDR/glow preparation fails later, the adapter still attempts one original text draw before reporting the error and rejecting generation; a failed final draw is not retried because it may already be partially visible. State restoration alone does not certify that omitted pixels were recovered. The extra HDR draw, bloom pyramid, Final copy and composite have real GPU/memory costs and run only for a visible relocated board with an observed world Bloom pass. Disabling FG leaves the existing pre-postprocessing SR-only navigation path unchanged.

World-color pool entries remain leased through the submission and the existing producer-copy/SDK-consumption fences. A transport slot is reusable only after both its image lease and shared GPU-ready fence retire; releasing a CPU frame does not retire a pending resample. Mandatory world/Final/temporal copies temporarily suspend the caller's D3D11 draw predicate and restore it, including on exceptions: a completion fence must not certify a copy that predication skipped. Callback admission is closed before final teardown drains; resize and backend changes serialize the world-copy producer across the complete surface transition. Frame IDs alone never certify GPU completion.

Depth and motion use the actual raster dimensions snapshotted before the SR image-effect path restores the camera's output target. They remain content-local even when the canonical H/Final are larger or contain borders. FSR receives the content rectangle and an independent maximum render size; its temporal inputs are not artificially restricted to being smaller than D. Streamline tags H and the backbuffer with the same valid extent, tags depth/motion with their full R extent, and derives camera aspect from the perspective projection scales rather than rounded raster or physical swapchain dimensions. The SDK applies the content-to-display mapping; the adapter must not apply an additional letterbox scale to motion or jitter. The texel domain, vector basis, non-jittered camera matrices and raster jitter are converted together from Unity render-texture coordinates to the native top-left content convention. On the D3D11 RT-reflected path this reorders depth/motion rows and uses motion scale `(-rasterWidth,+rasterHeight)` without negating the stored RG channels. Depth remains raw device depth with its reversed-Z flag; it is not linearized or replaced with `1-depth`. Matrix serialization then converts Unity column-vector transforms to Streamline's row-vector convention.

The camera's motion-vector request persists across frames. Restoring its flags at every EOF destroys Unity's previous-camera history even if motion vectors are enabled again in pre-cull. A newly acquired request first completes one render without publishing FG inputs; subsequent renders may generate frames. Turning FG off preserves the request while the same camera's SR path still needs it. Once no consumer needs the camera, or the camera becomes inactive/replaced, the adapter restores its unchanged original flag snapshot; disposal also releases the request. Unrelated flag changes by other components are not overwritten.

FSR receives Final in its proxy backbuffer plus `HUDLessColor`, using the SDK's native UI extraction. There is no application-produced occlusion alpha, residual image or UI presentation callback. The FG dispatch callback and SDK retirement remain necessary. DLSS tags HUDless, depth and motion without an application UI alpha/color surface, and disables optional UI Recomposition. This is not a promise of the best UI quality offered by a separately rendered UI layer: screen UI, bloom/blur and the navigation HUD still require game-specific visual acceptance. Both paths require matching color encoding/postprocessing, dimensions, camera data and valid resource lifetimes. Optional distortion inputs remain separate from UI handling.

FSR's SDK debug checker is off by default; GPU probes opt into the graphics debug layer separately. `generatedSubmissions` reports successful FSR dispatch submissions; for DLSS it is the nonnegative excess of SDK-reported presentations over application presentations. `sdkReportedPresents` retains DLSS's SDK counter separately. Neither field measures physical display FPS. The generation-enabled status bit describes accepted configuration/inputs, not a guarantee of extra presentation. In particular, Streamline may suppress generation for an unfocused window while reporting `eOk`; compare SDK/application counter deltas over the same interval and consult its diagnostics. Rendering rate, generated output, latency, frame pacing and validation overhead must be evaluated separately.


## Tests

`bridge-lifetime-fallback` uses the Windows WARP software device, not an NVIDIA GPU. It checks separate producer/consumer threads, resource retention after the caller drops its references, exact fallback pixels and actual descriptor diagnostics for an invalid depth format, cancellation, backpressure, retirement acknowledgement and shutdown/reinitialization. Its deliberately invalid depth rejects before NGX device initialization. Unequal-size tests validate the distinct input/output roles, preserve the exact prefill on validation errors, and exercise the production backup with an actual partial texture overwrite and recapture. Query tests check 1:1 DLAA results, pending/stale-result semantics, cancellation/COM lifetime, invalid arguments and shared frame/query backpressure without requiring NVIDIA hardware. Capability tests additionally check real WARP rejection with a reason, pending/terminal consumption, retained resources, cancellation, duplicate events and bounded unread results. The opt-in `bridge-tests <runtime> --hardware-support` repeats that query contract on the actual hardware adapter and requires DLSS availability; it creates no DLSS feature or visible window and is not part of default CTest.

`ngx-probe <runtime> <output> K --bridge-switch` additionally runs the real release/development NGX library on NVIDIA hardware. It switches K/F/L/M/E/K/K on one camera key, checks matching runtime evidence and finite output at every stage, then releases/shuts down. `--bridge-switch-typeless` runs the same sequence with Unity-style typeless color, output, depth and motion resources. The WARP lifetime/fallback test also has a typeless variant, preserving exact fallback pixels and rejection of the wrong depth format. The ordinary probe remains a single-preset backend test. Driver-profile isolation requires explicit opt-in; never run it implicitly from a build or CTest.

`ngx-probe <runtime> <output> K --jitter-stability` is a separate static-image diagnostic (`tools/run-preset-probes.ps1 -JitterStability`). It compares both jitter signs using the same stationary box and point-sampled thin diagonals, resets and warms up 64 frames per sign, then measures 32 frames. It writes edge-position CSV data, per-axis edge standard deviation, per-pixel temporal variation of the detail patch, and output images. These are image diagnostics, not timing assertions or a substitute for game motion/UV validation; they are not part of hardware-independent CTest.

`ngx-probe <runtime> <output> K --bridge-super-resolution` is an opt-in hardware diagnostic, never a default CTest dependency. It queries the real SDK for each mode, directly samples the synthetic scene at the resulting input resolution, and reconstructs to a fixed 1280×720 target. The sequence is DLAA/K, Quality/K, Balanced/K, Performance/M, Ultra Performance/L and Quality/E/L/M. Each stage checks its actual preset evidence, finite nonblack output, sampled D3D11 state and final camera/query retirement. It uses 32 frames per stage except Ultra Performance's 72-phase sequence, retaining the negative synthetic-projection jitter convention. Output dimensions and SDK ranges are printed beside each stage. Run via the project's bounded single-instance probe workflow; these checks do not prove Unity rendering, motion-vector correctness or in-game image quality.

`fsr-probe <AMD-runtime-directory> <output-directory>` exercises real capability/sizing/evaluation/retirement through the additive FSR exports, including an AMD-only runtime directory, typeless inputs, reactive-mask on/off, reversed/non-reversed depth and history resets. The default WARP suite separately checks FSR parameter ABI rejection, optional-input COM retention, exact unequal-size prefill preservation, backend-specific query cancellation and retirement without loading an AMD hardware runtime. Neither a static synthetic scene nor a descriptor test proves real game image quality.
